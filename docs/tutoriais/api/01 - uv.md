# UV 

O `uv` é um gerenciador de pacotes e mabientes Python escrito em Rust, criado pela Astral. é um substituto moderno e extremamenterápido para pip, pip-tools, venv e virtualenv.

## O que ele faz ?

Gerencia pacotes - instala, remove e resolve dependencias como o pip, mas ordens de magnitude mais rápido. 

Gerencia ambientes virtuais - cria e controla `.venv` como o `venv/virtualenv`.

Gerencia projetos — com uv init, uv add, uv run, funciona como um gerenciador de projeto à la poetry ou pdm, mantendo pyproject.toml e um uv.lock para reprodutibilidade.

Gerencia versões do Python — com uv python install 3.12, baixa e instala versões do Python sem precisar de pyenv.

## Na prática, o fluxo comum

- `uv init meu-projeto` - cria estrutura com pyproject.toml
- `uv add fastapi uvicorn` - adiciona dependências (substitui pip install)
- `uv run uvicorn main:app` - roda comando no ambiente virtual automaticamente
- `uv sync` - sincroniza ambiente com o lock file

## Por que usar em dez do pip ? 

- `Velocidade` — resolução e instalação muito mais rápidas
- `Lock file nativo` — uv.lock garante reprodutibilidade sem precisar de pip-tools
- `Tudo em um` — substitui pip + venv + pip-tools + pyenv com uma única ferramenta

## Iniciando o projeto

Iniciei o projeto com comando 

```bash
uv init integracao-hellow
```

Nele já temos a estrutura inicial criada:

```
integracao-hellow/
├── .python-version
├── main.py
├── pyproject.toml
└── README.md
```

- `.python-version` — define qual versão do Python o projeto usa. O `uv` lê esse arquivo para garantir que todos usem a mesma versão.
- `main.py` — ponto de entrada da aplicação, criado com um `Hello, World!` de exemplo.
- `pyproject.toml` — arquivo central do projeto: nome, versão, dependências e configurações. Substitui o `requirements.txt` e o `setup.py`.
- `README.md` — documentação inicial do projeto, gerada vazia pelo `uv`.
